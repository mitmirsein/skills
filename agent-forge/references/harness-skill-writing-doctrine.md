# 스킬 작성 원칙 (Harness Writing Doctrine)

> **출처**: revfactory/harness — skill-writing-guide.md 개념 이식 (Apache 2.0)
> **목적**: `agent-forge`가 새 스킬을 생성할 때 적용할 고품질 작법(Writing Patterns)

---

## 1. Description 작성: 트리거 메커니즘의 핵심

Description은 스킬의 **유일한 트리거 메커니즘**이다. 에이전트는 `available_skills` 목록에서 **name + description만** 보고 스킬 사용 여부를 결정한다.

### 작성 원칙 3가지
1. **스킬이 하는 일** + **구체적 트리거 상황**을 모두 기술한다.
2. **경계 조건**을 명시한다: 유사하지만 트리거하면 안 되는 경우를 구분.
3. 약간 **"pushy"하게** 작성한다: 에이전트의 보수적 트리거 성향을 보상.
4. **글자 수 예산(Budget) 엄수**: 영문 250자(국문 공백 포함 150자) 이내가 가시성 한계선이다. 이를 초과하면 시스템에서 스킬 트리거가 유실(Truncated)될 확률이 극도로 높아진다.

### ✅ 좋은 예
```yaml
description: "PDF 파일의 텍스트/테이블 추출, 병합, 분할, OCR을 포함한
  모든 PDF 작업을 수행. .pdf 파일을 언급하거나 PDF 산출물을 요청하면
  반드시 이 스킬을 사용할 것. 단순 열람이 아닌 변환/편집/분석이
  필요할 때 특히 유용."
```

### ❌ 나쁜 예
```yaml
description: "데이터를 처리하는 스킬"  # 너무 모호
description: "PDF 관련 작업"            # 동작 나열 없음, 트리거 상황 미기술
```

## 2. 본문 작성 스타일: 4대 원칙

### 원칙 1: Why-First (이유 우선)

에이전트는 이유를 이해하면 엣지 케이스에서도 올바르게 판단한다. 강압적 규칙보다 **맥락 전달**이 효과적이다.

```markdown
# ❌ 나쁜 예 (강압적)
ALWAYS use library-A. NEVER use library-B.

# ✅ 좋은 예 (이유 제시)
table 추출에는 library-A를 사용한다.
library-B는 텍스트 추출에 특화되어 있어 행/열 구조를 보존하지 못하기 때문이다.
library-A는 셀 경계를 인식하여 구조화된 데이터를 반환한다.
```

### 원칙 2: 일반화 (Generalization)

피드백에서 발견된 문제를 특정 예시만 처리하는 **좁은 수정**이 아닌 **원리 수준**에서 일반화한다.

```markdown
# ❌ 오버피팅 수정
"Q4 매출" 열이 있으면 숫자로 변환하라.

# ✅ 일반화된 수정
열 이름에 "매출", "금액", "수량" 등 수치를 암시하는 키워드가 있으면
해당 열을 숫자 타입으로 변환한다. 변환 실패 시 원본 값을 유지한다.
```

### 원칙 3: 명령형 어조

`"~합니다"`, `"~할 수 있습니다"` 대신 **`"~한다"`, `"~하라"`** 형태를 사용한다. 스킬은 지시서다.

### 원칙 4: 컨텍스트 절약 (Context Stewardship)

컨텍스트 윈도우는 공공재다. 모든 문장이 토큰 비용을 정당화하는지 자문한다:

| 자문 | 행동 |
|---|---|
| "에이전트가 이미 알고 있는 내용인가?" | 삭제 |
| "이 설명이 없으면 에이전트가 실수하는가?" | 유지 |
| "구체적 예시 하나가 긴 설명보다 효과적인가?" | 예시로 대체 |

## 3. Progressive Disclosure (점진적 공개) 패턴

모든 내용을 SKILL.md에 직접 쓰지 말 것. 중요도에 따라 계층화한다:

```
SKILL.md (항상 로드)
  └── 핵심 트리거 조건, 워크플로우 개요, 필수 원칙

references/ (필요 시 참조)
  ├── gotchas.md        ← (필수) 지식 함정 및 예외 케이스
  ├── 상세 패턴 문서     ← 복잡한 작업별 상세 가이드
  └── 예시 모음         ← 참고 사례
```

**원칙**: 스킬 본문은 에이전트가 **"무엇을, 왜"** 해야 하는지만 담는다. **"어떻게"**의 상세는 references에 위임한다.

## 4. 스킬에 포함하지 않을 것

다음은 스킬 문서에서 제거하거나 references로 이동해야 한다:

- **에이전트가 이미 아는 기초 지식**: `"Python은 들여쓰기가 중요합니다"` — 삭제
- **라이브러리 기초 사용법**: 공식 문서 URL 링크로 대체
- **일반론적 베스트 프랙티스**: 스킬의 특정 도메인에 맞게 정제하거나 삭제
- **과도한 예시 나열**: 3개 이상의 예시가 있다면 가장 대표적인 1~2개만 유지
