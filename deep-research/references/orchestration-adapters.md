# 오케스트레이션 어댑터

## 능력 탐지 순서

1. 현재 환경에서 웹 검색, URL 열기, 로컬 파일 읽기, 학술 검색, 서브에이전트 실행이 가능한지 확인한다.
2. 사용할 수 있는 도구만 계획에 넣는다. 설치되지 않은 MCP·플러그인·명령을 만들어내지 않는다.
3. 서브에이전트가 없으면 역할을 그대로 유지한 채 메인 에이전트가 순서대로 실행한다.

## 역할

| 역할 | 책임 | 우선 소스 |
|---|---|---|
| 발견 조사 | 용어·행위자·연구 지형 파악 | 개관, 최신 검색, 참고문헌 |
| 1차 자료 조사 | 핵심 주장에 직접 근거 확보 | 정부·법령·표준·원논문·공시 |
| 학술·기술 조사 | 방법과 전문 논쟁 확인 | 피어리뷰, 공식 명세, 원저장소 |
| 반증 조사 | 핵심 주장에 반대되는 자료 탐색 | 독립 1차 자료, 비판 연구 |
| 교차검증 | 중복·충돌·독립성 판정 | 전체 반환값 |

## 병렬 실행 규칙

- 사용 가능한 슬롯에서 메인 에이전트 자리를 제외하고, 한 배치에 최대 2~3개만 실행한다.
- 서로 다른 하위 문제처럼 독립적인 작업만 병렬화한다.
- 각 작업에 질문, 범위, 날짜 기준, 필요한 소스 유형, 반환 계약을 함께 전달한다.
- 한 배치의 반환값과 생존 여부를 확인한 뒤 다음 배치를 시작한다.
- 실패 시 더 작은 배치로 한 번 재시도하고, 다시 실패하면 순차 실행한다.

## 공통 반환 계약

각 조사자는 JSON 객체 또는 JSONL 레코드로 다음을 반환한다.

```json
{
  "subtopic": "검증한 하위 문제",
  "summary": "출처에 근거한 짧은 요약",
  "sources": [
    {
      "url": "https://example.org/source",
      "title": "원문 제목",
      "author": "저자 또는 기관",
      "published_at": "2026-01-31",
      "source_type": "official",
      "quality_rating": "B",
      "primary": true,
      "independence_group": "example.org",
      "claims": ["이 출처가 직접 지지하는 내용"]
    }
  ],
  "contradictions": [],
  "gaps": [],
  "failed_access": []
}
```

모르는 값은 빈 문자열이나 빈 배열로 두되 URL과 제목을 추측하지 않는다. `quality_rating`, `primary`, `independence_group`은 최종 병합 전에 메인 에이전트가 다시 확인한다.

## 도구별 적용

- Codex: 협업 도구가 노출된 경우 독립 하위 문제에만 작업을 배정한다.
- Claude Code: 사용 가능한 에이전트/Task 기능을 쓰되 권한 우회 옵션을 요구하지 않는다.
- Gemini 또는 단일 에이전트 환경: 동일한 역할 프롬프트를 순차 실행하고 각 결과를 즉시 파일로 저장한다.
- 검색 커넥터: 공식 문서나 전문 데이터베이스를 직접 제공하면 일반 웹 검색보다 우선하되, 하나의 공급자에 모든 검증을 의존하지 않는다.
