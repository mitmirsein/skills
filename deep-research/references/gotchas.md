# 알려진 함정

## 조사 범위

- 역사·고전 주제의 모든 검색어에 현재 연도를 강제로 붙이지 않는다. 최신 연구사나 현재 논쟁을 찾을 때만 날짜를 추가한다.
- 넓은 질문을 5개보다 많은 하위 문제로 잘게 쪼개면 중복 검색과 합성 비용이 급증한다. 먼저 3~5개로 시작하고 실제 공백이 확인될 때만 추가한다.
- 사용자가 이미 독자, 시점, 산출물을 명시했으면 다시 묻지 않는다.

## 출처와 독립성

- 같은 보도자료를 재전재한 여러 기사, 같은 데이터셋을 재인용한 보고서, 모회사와 자회사의 문서는 독립 출처로 세지 않는다.
- 검색 결과 스니펫, AI 요약, 인용문 재인용은 원문 확인이 아니다.
- URL 접근 실패는 주장의 거짓을 뜻하지 않는다. `failed_access`로 기록하고 대체 1차 출처를 찾는다.
- A–E 등급은 권위의 절대 순위가 아니다. 질문 유형에 맞는 직접성·방법·최신성을 함께 평가한다.

## 오케스트레이션

- 특정 제품의 도구명, 서브에이전트 수, 권한 우회 옵션을 가정하지 않는다.
- 병렬 작업이 실패하거나 반환값이 비어 있으면 같은 배치를 무한 재시도하지 않는다. 한 번 축소 재시도한 뒤 순차 조사로 전환한다.
- 서브에이전트가 만든 파일만 믿지 말고 반환 경로와 최소 필드를 직접 확인한다.

## 검증 게이트

- Claim Ledger는 문장 유사도를 판정하지 않는다. 보고서의 핵심 주장이 실제 근거와 같은 의미인지 사람이 읽어 확인해야 한다.
- `[clm_001]` 표시는 감사 추적용이지 독자용 인용을 대신하지 않는다.
- `evaluate_report.py`는 출처 ID 해소와 미확정 주장 위치를 검사하지만, 인용이 문장을 의미론적으로 지지하는지는 자동 보장하지 않는다.
- 검증되지 않은 주장을 삭제해 점수만 높이지 않는다. `Unresolved`에 남기고 필요한 추가 조사를 설명한다.

## 저장과 재개

- 연구 산출물은 스킬 폴더 밖에 둔다. 스킬 업데이트와 세션 데이터가 섞이면 동기화·버전 관리가 깨진다.
- `state.json`만 갱신하고 실제 산출물을 만들지 않은 상태를 완료로 표시하지 않는다.
- 다른 컴퓨터에서도 재개할 수 있도록 절대 사용자 경로를 상태 파일에 저장하지 않는다.
