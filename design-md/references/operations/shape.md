# 동사: shape — 코드 전 설계 인터뷰

코드를 한 줄도 쓰기 전에 **디자인 브리프**를 뽑는 단계. "상상해서 그리기"의 가장 큰 원인은 의도 미확정이다.

## 언제
- 새 화면/컴포넌트 생성, 또는 모호한 요청("멋지게 만들어줘").

## 절차
1. 다음을 1~2개씩만 빠르게 확정한다(과하게 묻지 말 것):
   - **목적·핵심 행동(primary action)**: 사용자가 이 화면에서 *한 가지* 하게 할 일.
   - **콘텐츠 유형**: SaaS UI / 랜딩 / 대시보드 / 장문 에디토리얼 / 설교·저널 / 문서.
   - **출력 타깃**: HTML·React / Obsidian-native / 인쇄(PDF). → [adapt.md](./adapt.md)
   - **브랜드 톤**: canon 지정 또는 추정값 한 줄 제안.
   - **밀도**: 정보 밀집형 vs 여백 중심 에디토리얼.
2. 위를 **디자인 브리프 5줄**로 요약해 사용자에게 확인받는다(또는 자명하면 명시 후 진행).
3. 브리프를 이후 모든 동사의 기준선으로 고정한다.

## 산출물 (브리프 템플릿)
```
목적:        (한 문장)
핵심 행동:    (버튼/링크 1개)
콘텐츠 유형:  …
출력 타깃:    …
브랜드/톤:    canon=…  무드=…
밀도/측정폭:  …
```

## 함정
- 인터뷰를 빌미로 10개씩 묻지 말 것. 자명한 것은 합리적 기본값으로 정하고 한 줄로 통지.
- 브리프 없이 Phase 3로 직행하면 critique에서 "의도 불명"으로 감점된다.
