# 동사: colorize — 브랜드 색 → OKLCH 팔레트 적용

색을 hex로 흩뿌리지 않고, [tokens/oklch-base.md](../tokens/oklch-base.md)의 토큰 시스템을 통해 일관·튜닝 가능·접근성 보장된 팔레트로 적용한다.

## 절차
1. brand canon에서 시드 색(primary/accent)을 가져온다 — 이는 *시드*일 뿐 최종값이 아니다.
2. oklch-base.md의 방식으로 시드를 OKLCH로 변환하고 **명도 사다리**(L 95→10)를 파생해 `--color-…-50..900`을 만든다.
3. 시맨틱 토큰으로 매핑: `--bg`, `--surface`, `--text`, `--text-muted`, `--border`, `--primary`, `--accent`, `--danger` 등. 컴포넌트는 *시맨틱 토큰만* 참조한다.
4. 라이트/다크는 같은 H/C에서 L만 반전·재배치해 파생(다크에서 채도 소폭 ↓).

## 색 사용 원칙
- 무채색 베이스 + 절제된 1~2개 강조색. 무지개 팔레트 금지.
- 강조색은 primary action·핵심 데이터에만. 남발하면 위계가 죽는다.
- 회색도 순회색(#888) 말고 브랜드 H를 미세 주입한 *따뜻한/차가운 회색*으로(OKLCH로 쉬움).
- 의미색(성공/경고/위험)도 토큰화하고 대비 4.5:1 확보(gotchas §6).

## 창발: 전례·계절 변주
- 에디토리얼/Kerygma 콘텐츠는 oklch-base.md의 전례력 팔레트(대림·사순·성탄·부활 등)를 H 회전으로 파생해 같은 명도 구조 위에 색조만 바꾼다.

## 함정
- canon hex를 컴포넌트에 직접 박기 → gotchas §1 위반.
- 다크모드를 색 반전(invert)으로 때우기 → L 사다리를 다시 설계해야 함.
