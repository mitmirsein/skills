# 🧠 NotebookLM Researcher 3.0: Gotchas & Anti-Patterns

NotebookLM 기반 심층 연구 수행 시 에이전트가 주의해야 할 사항입니다.
v3.0에서 Plan Mode, Scout Mode 추가에 따른 새로운 함정이 포함됩니다.

---

## 1. Discovery Pitfalls (발견의 함정)
- **표면적 요약**: "이 노트북이 무엇에 대한 것인가?"라는 질문에 일반적인 답변만 내놓지 마십시오. "우리의 [X] 연구와 어떤 지점에서 충돌하거나 보완되는가?"라는 연결 고리를 찾으십시오.
- **환각(Hallucination)**: NotebookLM이 소스에 없는 내용을 지어내는지 인지하십시오. 반드시 "출처(Citation)를 포함해줘"라고 요청하십시오.

## 2. Plan Mode Pitfalls (사전 질문 설계의 함정) ⚡ NEW
- **질문 중복**: 6축으로 질문을 분배해도 실질적으로 같은 내용을 묻는 질문이 만들어질 수 있습니다. 생성 후 반드시 중복 검사를 수행하십시오.
- **과잉 질문**: 소스가 2~3개뿐인 노트북에 15개의 질문을 던지면 대부분 "관련 정보 없음"이 반환됩니다. **소스 수 × 3** 이하로 질문 수를 제한하십시오.
- **목표 이탈**: "강의자료용"이라는 목표가 주어졌는데, 지나치게 학술적이거나 미시적인 질문을 설계하지 마십시오. 항상 목표를 재확인하십시오.

## 3. Recursive Loop Failures (재귀 루프 실패)
- **비생산적 질문**: "더 알려줘"와 같은 막연한 후속 질문은 토큰만 낭비합니다. 구체적인 키워드나 논리적 모순점을 지적하는 질문을 던지십시오.
- **루프 탈출 실패**: 정보가 포화되었음에도 기계적으로 질문을 반복하지 마십시오. Nash Equilibrium 탈출 조건(소스 포화 3회, 정보량 체감, 최대 7회)을 엄격히 준수하십시오.

## 4. Scout Mode Pitfalls (소스 발굴의 함정) 🌐 NEW
- **소스 과잉 임포트**: Deep Research로 40개 소스가 발견되어도, 무분별하게 전부 임포트하면 노트북의 맥락이 희석됩니다. **상위 5~10개만 선별**하십시오.
- **저품질 소스**: 웹 검색 결과에는 광고성 블로그나 얕은 요약 포스팅이 포함될 수 있습니다. 학술적 신뢰도를 기준으로 필터링하십시오.

## 5. Execution Errors (실행 오류)
- **MCP 인증 만료**: `mcp_notebooklm_refresh_auth`로 즉시 재인증하십시오. 401/403 에러 발생 시 재인증 가이드를 제시하십시오.
- **노트북 ID 혼동**: 여러 개의 노트북을 동시에 다룰 때, 엉뚱한 노트북 ID에 쿼리를 날리지 않도록 매 단계 검증하십시오.
- **Conversation ID 미사용**: 동일 주제의 후속 질문 시 `conversation_id`를 전달하지 않으면 NotebookLM이 문맥을 잃습니다. Dive Mode에서는 반드시 conversation_id를 연쇄 전달하십시오.
- **⚠️ 쿠키 추출 부족 (신규)**: `nlm login` 첫 실행 시 새 Chrome 창이 열리면 쿠키가 19개만 추출되어 인증에 실패할 수 있습니다. 이때 **Chrome을 열어둔 채로 `nlm login`을 한 번 더 실행**하면 이미 실행 중인 Chrome 인스턴스에서 104개 쿠키를 올바르게 추출합니다. 인증 성공 후 MCP 서버에도 `mcp_notebooklm_refresh_auth`를 호출하여 토큰을 갱신하십시오.

## 6. Citation Mapping Errors (인용 오류) 📎 NEW
- **인용 번호 미매칭**: NotebookLM이 반환한 `[1]`, `[2]` 번호가 실제 소스와 다를 수 있습니다. 보고서 작성 시 `source_describe`로 교차 검증하십시오.
- **인용 누락 무시**: 답변에 인용이 하나도 없으면 그냥 넘기지 마십시오. "출처를 포함하여 다시 답변해 주세요"로 재질의하십시오.
